# 并行子任务

主助手可用 `agent_spawn` 委派独立任务，再用 `agent_collect` 收集结果并汇总。启动工具立即返回任务 ID，不等待子任务结束；多个子任务使用同一个 Agent 执行循环的独立实例，真正并发请求模型。主助手可继续调用其他工具。

## 使用与限制

- 每次主请求最多创建 6 个子任务，同时最多 3 个；每个子任务最多 6 轮模型调用。主任务沿用现有步数限制（聊天默认 8）。等待收集结果不反复调用模型、不消耗额外步骤。
- 仅一层。子任务的工具中没有 `agent_spawn` / `agent_collect`，也没有全局 MCP 注册、安装和激活管理工具。
- 启动参数为 `title`、`task`，可附 `context`；只传必要材料，不自动复制主会话历史。标题最多 120 字符，任务与上下文各最多 8000 字符。
- 子任务沿用本次主请求开始时的模型、凭据、全局助手设定和授权目录。设置改变只影响下一次主请求。每个任务的 `tool_introspect` 反映自己的实际工具快照。
- `agent_collect` 接受本次请求的 `taskIds` 和可选 `wait`（默认 true）。返回任务状态及最多 12000 字符的最终回答或错误；不返回私有模型推理。
- 若主助手没有显式收集就结束回答，Host 等待未汇报的子任务，将标明来源的、不可信的结果报告追加到模型私有上下文，要求主助手续答。它不是用户聊天消息，不生成伪造的模型工具调用；续答仍占主任务步数，预算不足会明确失败，不无限循环。

## 停止、审批与历史

每个子任务卡片显示状态、可展开的执行过程和「停止」按钮。待审批与待回答内容始终在折叠区外，并显示子任务名称。回答问题不代表授权，批准只作用于该子任务的一次工具调用。

停止某个子任务会取消对应模型请求以及审批、问答和工具等待，不影响兄弟任务。停止主任务或关闭 Host 会取消全部子任务。切换会话不会停止文件任务；网页工具仍遵守既有当前会话及页面身份检查。运行中的会话不能归档。

已完成的写入或第三方外部副作用不会回滚。不配合取消的第三方操作可能继续在服务内结束，Wisp 不接纳其迟到结果，也不宣称撤销成功。日志按父 run ID 关联子任务，重启仅恢复历史并标记未完成任务中断，不自动重放。

## 并行权限与文件冲突

内置文件工具仍限于已授权会话/项目目录。变更仍逐次审批；写入和定点替换在准备时绑定文件版本，批准后在 Wisp 变更锁内重新检查，发生并发变更时拒绝覆盖。外部程序与文件系统之间的极短竞态不构成 OS 级事务保证。

已激活第三方 MCP 工具仍逐次审批，同一任务家族的 MCP 调用串行执行。MCP 运行于用户系统权限，不能根据不透明的工具参数推断资源冲突，也不能事务回滚；不要委派会互相覆盖同一外部资源的任务。内置文件操作与第三方 MCP 的外部写入不共享系统级锁。

Web 的「并行子任务」QA 场景仅为内存界面样例，不证明真实模型并发或 Electron 实机执行。
